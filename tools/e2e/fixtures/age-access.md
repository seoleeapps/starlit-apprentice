# 연령 보호 개발 환경 여정

이 문서는 구현 사전검사 사양이다. 정식 UI5~7의 계획이나 통과 근거가 아니다. 최종 후보 SHA와 중앙 기록 양식이 확정된 뒤 각 회차 계획을 먼저 작성한다. 기존 UI1~4의 원본과 판정은 보존한다.

`fakes/age_signals.gd`는 네이티브 `SaAgeSignalsAdapter` 응답만 바꾼다. 기본 대역은 비Android의 `unsupported` 응답으로 기존16개 시나리오를 유지한다. 공유 응답, 보류 응답, 이전 요청 ID의 늦은 응답, 동일 ID의 중복 응답, 해제 뒤 응답을 만들 수 있고 요청 횟수와 ID를 관측한다. 실제 SDK, Play 계정, 네트워크와 기기는 실행하지 않는다.

`age_access_cases.gd`의 새 시나리오는 실제 main장면을 띄우고 시작, 이어하기, 재확인, 닫기와 언어 버튼에 좌표 입력을 넣는다. `refresh_age_access()` 직접 호출은 OS 재활성화 경계의 알림 대역에만 사용한다. 게임 콜백과 신호는 직접 실행하지 않는다. 보호 사유와 응답 상태는 읽기만 한다.

| 시나리오 | 확인 항목 |
| --- | --- |
| `age-shared-allowed` | 공유된13~15세,16~17세와18세 이상에서 실제 새 게임 진입, 이미 끝난 조회의 중복 응답 무시 |
| `age-unshared-fallback` | `not_shared`, `unknown`, `offline`, `unavailable`, `error`, `unsupported` 구분과 기존 저장 이어하기 |
| `age-restricted-preserves` | 공유된13세 미만, 보호자 승인 대기와 거절에서 시작과 이어하기 차단, 닫기와 언어 전환 뒤에도 보호 유지 |
| `age-pending-timeout` | 실제5초 비동기 상한, 자동 반복 없음, 시간 초과 뒤 늦은 제한 응답 무시, 이후 실제 게임 이용 |
| `age-retry-and-stale` | 재확인과 OS 복귀의 중복 요청 방지, 이전 ID 무시, 이미 제한된 상태의 일시 실패는 제한 유지, 새 유효13세 이상 응답으로만 복구 |
| `age-lifecycle-and-release` | 미확인 이벤트 중 OS 복귀, 보호 안내와 게임 상태 보존, 장면 해제와 늦은 응답, 새 장면의 이어하기 |

저장 fixture는 실제 콘텐츠 전체로 `SaRunController`를 시작하고 실제 행동을 해결해서 만든 pending 저장이다. 이를 별도 임시 파일에 넣으며 실행 중인 컨트롤러의 pending, RNG와 상태를 수정하지 않는다. 기존 엔딩과 수동 연령을 담은 메타도 별도 파일에 복사한다. 각 SDK 응답 전후 런, 메타와 백업 파일의 SHA256, 수동 광고 연령과 광고 대역 호출을 비교한다. 실제 Play 연령이나 그 파생값을 수동 연령, 광고 입력과 저장에 쓰지 않는지 확인한다.

렌더링 모드에서는 공유 허용, 미공유와 오류 상태의 타이틀, 보호 안내, 확인 중 화면, 재확인과 재활성화 복구 화면을 남긴다. 한국어와 영어,640x1136,720x1280,720x1600의 정식 독립 검수는 별도 승인된 회차에서 수행한다.
