# 수정 이벤트의 저장 fixture

`rating-events.json`은 콘텐츠 변경 7건을 실제 이어하기 화면에서 확인하기 위한 합성 저장 입력 사양이다. 실행 결과나 검수 완료 근거가 아니다.

`fakes/rating_event_fixture.gd`는 실제 콘텐츠 전체와 `SaRunController`를 쓴다. 새 런의 저장 복사본에 턴, 자원, 이전 이벤트 기록 등 합성 시작 조건을 넣고 복원한 다음 실제 행동을 해결한다. 대상 이벤트가 첫 pending으로 생성되는 seed만 고른다. 성공과 실패 분기는 별도 컨트롤러 복사본으로 예측해 재현할 RNG 상태를 찾는다. 예측한 결과문이나 pending 목록을 게임 객체에 넣지 않는다.

여정은 생성된 `controller.to_save()`를 격리 파일 저장소에 쓰고 실제 `main.tscn`의 이어하기 버튼, 이벤트 선택지와 계속 버튼에 좌표 입력을 넣는다. 장면의 게임 콜백, 신호, `pending_events`와 상태를 직접 변경하지 않는다. 입력 저장 파일, seed, 시도 횟수와 SHA256은 실행 때만 `fixture-inputs/` 및 `journey.json`에 기록한다.

기존 9개 시나리오 뒤에 다음 7개 시나리오를 더하며 입력 저장은 총 17개다.

| 이벤트 ID | 선택 및 분기 |
| --- | --- |
| `cond.burnout.enter` | 따뜻한 식사와 휴식 선택과 결과 |
| `milestone.s3.favorite` | a와 b의 성공 및 실패, c의 결과 |
| `npc.rival.eden.03` | 식은 차 장면의 본문과 a 선택 |
| `npc.rival.eden.05` | 경쟁 대신 함께 관측하는 b 선택과 결과 |
| `opp.plague-ward` | a 성공의 깨끗한 이불 문구, b의 식량과 이불 선택 |
| `opp.wager-table` | 금화 0과 120에서 a 성공 및 실패, b와 c의 결과 |
| `world.guild-dispute` | c 결과의 식사와 차 문구 |

예보 의뢰는 금화 0과 120에서 실제 선택 버튼이 활성화되고 참가비 없이 성공 시 200금화만 늘고 실패 시 금화가 줄지 않는지 확인한다. 다른 이벤트도 본문, 선택지와 결과가 해당 언어의 원본과 일치하는지, 수정된 문구가 표시되는지, 결과 자원과 저장이 이어지는지 확인한다. 각 입력의 이벤트 화면과 결과 화면을 렌더링 때 남긴다.

추가 독립 검수 4회부터 6회까지의 계획과 실행 근거는 후보 SHA를 동결한 뒤 각 회차 시작 전에 별도로 작성한다. 이 사양 추가만으로 새 회차나 Godot 실행을 시작하지 않는다. 기존 1회부터 3회까지의 근거는 수정하지 않는다.
