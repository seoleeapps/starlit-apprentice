# 별빛 견습생 Android 공개 출시

상태: 사용자가 2026-10-21 대화에 제시한 계획을 구현하도록 지시했다. 이 문서는 그 승인 범위를 고정한다. 실행과 공개 완료는 별도다.

## 목적과 범위

Seolee Apps 개인 계정 5547060480954653351에서 com.seorilabs.starlitapprentice를 무료로 출시한다. 한국 포함 배포 가능한 전체 국가, 13세 이상, 한국어와 영어, 표시 버전 1.0.0, 공개 비율 100%다. 기존 아트와 화면 방향을 유지한다. Godot 4.7.2를 유지하며 Firebase, GA4 전송, 원격 설정과 서버 광고 검증을 제거한다. 저장은 기기에 남는다. iOS와 AppsInToss 출시, 배너, 보상형, 결제는 범위 밖이다.

## 흐름과 책임

타이틀에서 언어, 소리, 연령대와 광고 개인정보 설정을 바꾼다. 언어 변경은 진행과 저장을 유지한다. 기본 언어는 한국어 기기는 한국어, 나머지는 영어다. 콘텐츠의 stable ID로 번역하며 코어의 판정 값과 콘텐츠 ID는 바꾸지 않는다.

기존 화면 기준은 docs/game-design/03-ui-ux-spec.md와 assets/art/style/style-guide.md다. 신규 시각 방향 선택 없이 승인된 화면에 설정을 추가한다. 긴 본문은 스크롤하며 작은 화면, 기준 화면, 긴 화면과 두 언어를 실제 렌더링한다.

월말 행동 결과 확인, 해당 턴의 모든 이벤트와 결과 확인, 저장 성공, 준비된 광고 확인, 광고 표시, 다음 행동 화면 순서로 진행한다. 엔딩 직전에는 광고를 생략한다. 첫 달을 튜토리얼로 보고 광고를 생략한다. 광고 미준비, 실패, 동의 미확정이면 기다리지 않고 게임으로 복귀한다. 늦은 로드 콜백은 광고를 표시하지 않는다.

게임은 광고 준비와 표시 요청 인터페이스만 본다. Poing AdMob v5.1.0과 UMP 호출은 Android 어댑터에 둔다. 시계, 난수, 저장, 광고만 테스트에서 바꾼다. 정책은 로컬 JSON에서 읽는다. 최초 180초, 종료 후 최소 120초, 세션 6회, UTC 하루 20회, 30분 비활동 시 새 세션을 적용한다. 실제 impression 콜백으로 횟수를 저장하며 중복 표시와 중복 콜백을 막는다. 시도 중 재실행은 보수적으로 예약 횟수를 반영한다.

연령대 unknown, under13, 13-15, 16-17, adult만 저장한다. unknown과 under13은 SDK 광고 요청을 하지 않는다. 청소년은 UMP와 광고 요청 양쪽에 연령 제한을 적용한다. 지역별 동의를 확인할 수 없으면 광고를 생략한다. 동의 철회 화면 진입 시 준비한 광고를 폐기한다. 운영 ID 미확정은 광고 준비 불가로 처리하고 출시 검사는 실패시킨다.

## 실패, 저장과 복구

설정과 광고 횟수는 원자적 메타 저장을 사용한다. 저장 실패를 화면에 알리고 재시도를 제공하며 광고를 생략한다. 손상된 저장은 직전 백업을 읽고, 복원할 수 없으면 사용자 선택 없이 새 런으로 대체하지 않는다. 엔딩 기록 저장에 실패하면 런을 지우지 않는다. 테스트 데이터는 전용 임시 경로로 격리한다.

## 인수조건과 검증

- AC-01: 런타임과 빌드에 서버 인증, 분석 전송, 원격 설정이 없다.
- AC-02: 한국어와 영어에서 36턴, 이벤트, 정산, 엔딩, 재실행, 이어하기와 저장 복구가 같은 규칙으로 동작한다.
- AC-03: 광고 연령, 동의, 시간 경계, 상한, 날짜 변경, 재실행, 중복 콜백, 실패와 저장 실패를 검증한다.
- AC-04: 실제 시작 장면의 좌표 입력과 카드 드래그를 사용하며 모든 기능을 기능 목록 v2와 E2E 시나리오에 연결한다.
- AC-05: 캐시 없는 첫 import부터 두 번의 별도 fresh 검증이 모두 통과한다. 모든 Godot 호출은 timeout, ANSI 제거와 오류 로그 판정을 적용한다.
- AC-06: 두 언어, 세 화면 크기의 실제 렌더링과 독립 검수 3회를 기록한다. 검수자는 구현자와 다르다.
- AC-07: 명시적 출시 태그만 서명 빌드와 업로드를 실행한다. 중앙 원장, before-build, before-deploy, before-release 검사와 같은 후보 SHA 근거를 사용한다.
- AC-08: 운영 광고 ID, target API 36 이상, 패키지, 버전, 서명, Firebase 의존성 부재와 16KB 페이지 호환성을 최종 AAB에서 확인한다.
- AC-09: 내부 업로드, production 승격, 심사, 승인, 게시, 공개 버전 확인을 각각 기록한다.

L3 전체 회귀의 기본 환경은 dev다. Android에는 SDK 표시, 동의, 닫기와 복귀만 추가한다. 기기로 확인해야 하는 이유는 headless의 대체 광고가 Android SDK와 UMP를 실행하지 않기 때문이다. 기기 실행은 별도 명시적 사용 승인 뒤 독립 검수자가 Android 1대로 진행한다. 공개 설치 출처와 버전 확인 포함 총 25분, 최대 2회. 삭제, 초기화, 계정과 OS 설정 변경, 광고 클릭을 제외한다. 이 계획 구현 지시만으로 기기 사용을 승인받았다고 기록하지 않는다.

TDD는 광고 정책, 저장 실패와 번역 완전성에 적용한다. SDK, 콘솔, 에셋의 실제 동작은 단위 테스트로 증명할 수 없어 개발 실행, 산출물 검사와 승인된 네이티브 실행으로 검증한다.

## 출시, 권한과 운영

계정과 패키지 소유, 기존 인증서를 live readback한다. 다른 소유자면 멈춘다. 신규 등록과 기존 키 부재가 확인된 경우만 앱 전용 업로드 키 생성 범위가 유효하다. 다른 앱 키 재사용, 기존 키 교체와 Play 권한 확대는 하지 않는다. 키 백업과 복원 검증 후에만 GitHub에 실행 복제본을 둔다.

기존 최댓값을 조회해 versionCode를 원장에서 할당한다. 내부 테스트에서 확인한 같은 AAB를 production으로 승격한다. 개인정보처리방침, SDK 기준 Data safety, IARC와 한국 등급, AdMob 앱 연결과 app-ads.txt는 출시 전 확인한다. 기존 스토어 자료를 현재 UI 증거로 사용하지 않는다.

광고 문제가 확인되면 추가 승격을 중단하고 로컬 정책을 끈 새 수정 버전을 검증한다. 기존 데이터와 키를 삭제하거나 교체해 복구하지 않는다. 서버 리소스는 생성하지 않는다.

실행 원장은 docs/06-release, 기능 목록은 docs/qa/feature-inventory.json이다. .serena는 사용자 작업으로 보존한다. 미출시에는 main 직접 반영, 공개 이후에는 브랜치와 PR을 사용한다.
