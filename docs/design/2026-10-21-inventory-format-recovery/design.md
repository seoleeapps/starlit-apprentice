# 기능 목록 형식 수정과 검수 후보 재고정

상태: 추가 검수 승인 대기. UI8~10은 계획과 실행을 시작하지 않았다.

2026-10-21T14:10:02Z에 후보 `62e76cc379ee95b1cc2f781a2e64c2a8b521505e`의 실제 중앙 before-build 검증이 `SOURCE_FEATURE_INVENTORY_REQUIRED`로 실패했다. 기능 목록의 save와 localization에 있는 `platformPaths: []`가 원인이다. 중앙 `f73637d7855a726e083da76fde82a6499ed53972`는 선택 경로 필드가 있으면 비어 있지 않은 배열을 요구하며, 빈 배열을 거절하는 회귀 검사도 있다. 중앙 검증기를 완화하거나 다른 목록으로 바꿔 통과시키지 않는다.

## 수정과 현재 근거

`docs/qa/feature-inventory.json`에서 이 두 빈 선택 필드만 제거한다. 실제 경로와 기능 ID, 광고와 연령 SDK의 플랫폼 경로는 유지한다. 게임, 화면, 번역, 저장과 native 소스는 바꾸지 않는다. 수정한 목록은 최신 중앙 `validInventory` 검사와 기존 세 승인 테스트 계획의 형식 검사를 통과했다. 이는 전체 출시 gate 통과가 아니다.

기존 후보의 전체 CI39606052628 성공과 최초 CI39602617715 실패를 보존한다. UI5의 입력 누락 실패, 같은 경로의 UI6과 UI7 재검수 통과, 원인 미확정과 개별 continue 입력 소비의 관찰 한계도 유지한다. 원래 후보의 판정과 SHA를 새 후보로 바꾸지 않는다. 기존 승인 설계와 이 자료는 새 후보에 대한 실행 통과로 세지 않는다.

## 제안하는 추가 검수

기존 상한7회는 모두 사용했다. 형식 수정과 승인 기록을 포함한 새 후보를 한 SHA로 고정한 뒤, 독립 UI8~10까지 세 회차를 추가한다. 새 회차는 앞 회차 완료 뒤에 계획하고 각각 한 번 실행한다. 각 회차는 기존 11기능, 한국어와 영어, 640x1136과 720x1280 및 720x1600의 6조합, 조합마다 기존 22시나리오와 실제 PNG 검수를 포함한다. 제품, 입력 도우미와 단언은 기존 검수에서 바꾸지 않는다. 추가 검수 예상 시간은 20분이며 최대 회차는10이다. 추가 실패는 보존하고 임의로11회차를 시작하지 않는다.

L3 전체 회귀의 기본 환경은 dev다. 새 SHA의 깨끗한 CI checkout에서 첫 import부터 두 번의 전체 회귀와 quality gate를 실행한다. UI 실행 전에 중앙 기능 목록 검사도 먼저 확인한다. 기존 독립 검수1~7의 실제 기록은 원래 순서와 승인 상한, 시각과 해시로 보존하고 새8~10만 현 후보의 검수 수로 센다. 최신 중앙 양식이 지원하는 완전한 과거 회차 보존 경로를 사용한다. 같은 후보, 전체 기능, 독립 검수, 실행 전 계획과168시간 조건은 유지한다.

새 회차 승인 전에는 UI8~10을 계획하거나 실행하지 않는다. 지금의 형식 수정은 이미 승인된 기능 목록과 검증 연결을 고치는 작업이며, 검수 횟수 증가는 이 보완안의 별도 승인 대상이다.

## 인수조건과 출시

- IF-01: 빈 선택 필드 두 곳만 제거하고 모든 비어 있지 않은 경로, 기능 ID와 런타임 파일을 보존한다.
- IF-02: 새 후보의 기능 목록과 승인 테스트 계획이 중앙 형식 검사를 통과하고, 같은 후보의 깨끗한 CI 전체 검증을 통과한다.
- IF-03: 새 후보의 독립 UI8~10을 승인된 순서와 전체 범위로 실행하고 원래 실패와 재검수 근거를 보존한다.
- IF-04: 실제 중앙 before-build 검증 뒤에만 태그와 서명 빌드를 실행한다. 내부 업로드와 공개는 기존 단계별 조건을 유지한다.

게임 동작 변경이 없는 메타데이터 수정은 정확한 diff와 경로 및 런타임 파일 보존 대조, 중앙 형식 검사로 검증한다. 과거의 제품 요구사항 실패 로그를 이번 형식 수정의 test-first 근거로 바꾸지 않는다.

기존 Google Play 무료 공개, 한국을 포함한 전체 가능 국가, 13세 이상과100% 공개 범위를 유지한다. WIF 권한 확대, 새 자격증명과 계정 변경은 없다. 기존 등록된 공통 Publisher의 로컬 내부 업로드 경로를 사용한다. 기기 조회와 실행은 승인 범위가 아니며 실제 Android 광고, UMP와 Age Signals 검수는 서명 AAB 준비 뒤에 별도로 소명한다. 현재 서명 AAB, 내부 업로드, 심사 제출과 공개는 미실행이다.
